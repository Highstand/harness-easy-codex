# 우리 브랜드 콘텐츠 자동화 — Codex 하네스 버전

기존 Figma × Claude 기획안의 조사→기획→프리뷰→Figma 흐름을 Codex로 옮긴 촬영 메모입니다.
원격 기획안과 Figma 장표는 수정하지 않았습니다.

| 구간 | 화면 | 설명 포인트 |
|---|---|---|
| 도입 | 예제 결과·폴더 | 자연어 요청으로 진행하되 중간에 사람이 결정한다 |
| 두 가이드 | brand.md / content-design.md | 브랜드가 할 말과 보여주는 기준을 구분한다 |
| 하네스 | AGENTS.md / 프로젝트 스킬 두 개 | 진행 규칙과 담당 절차를 파일로 준비했다 |
| 원본 확인 | 원본 링크·SVG | 문서의 설명과 실제 로고 파일은 다르다 |
| 조사 | Aside·posts.json·패턴 보고 | 경쟁사 구성에서 아이디어를 얻고 브랜드 기준에 맞게 해석한다 |
| 기획 | 주제 3개·plan.md | 사람이 주제와 카피·CTA를 결정한다 |
| 제작 | 새 이미지·HTML | 최종 이미지가 들어간 시안을 반드시 확인한다 |
| Figma | 새 섹션·텍스트 편집 | 확정 시안을 편집 가능한 결과로 옮긴다 |
| 마무리 | 검수·다음 주제 | 이번 수정과 공통 기준을 구분해 남긴다 |

도입 멘트:
“이번에는 콘텐츠를 만드는 순서까지 폴더에 준비했어요. 경쟁사 자료를 살펴보고, 우리 브랜드에 맞는 기획을 정한 뒤, 시안을 확인하고 피그마로 옮겨볼게요.”

하네스 설명:
“brand.md는 브랜드 소개서, content-design.md는 시각 기준이에요. AGENTS.md에는 진행 순서가 있고, 두 스킬에는 조사와 제작 방법이 담겨 있어요. 사용자는 긴 프롬프트를 외우지 않고 필요한 일을 말하면 됩니다.”

학습 설명:
“여기서 학습은 AI가 문서와 원본을 읽고 이번 작업의 맥락으로 활용한다는 뜻이에요. 모델을 새로 훈련하는 과정은 아닙니다.”

조사→기획 연결:
“경쟁사와 똑같이 만드는 게 목표는 아니에요. 반복해서 보이는 구성과 주제를 살펴보고, 우리 고객에게 필요한 이야기로 바꿔볼게요.”

프리뷰→Figma 연결:
“이제 로고, 카피, 사진과 글자 크기를 함께 확인해요. 이 시안으로 확정하면 피그마에 옮기고, 옮긴 결과도 비교합니다.”

시연 프롬프트:

```text
경쟁사 분석해줘.
```

```text
새 주제 3개 추천해줘.
```

```text
1번으로 5장 기획해서 plan.md에 정리해줘.
```

```text
이 기획에 맞는 새 이미지로 HTML 프리뷰를 만들어줘.
```

```text
이 프리뷰로 확정할게. 아래 피그마에 만들어줘.
[결과 링크]
```

촬영 전에는 로그인·Figma 쓰기·이미지 생성·폰트 로딩을 실제로 한 번 확인합니다.
수집 시간을 편집으로 줄이거나 포함된 예제로 전환하면 “미리 수집한 자료”라고 알립니다.
PPTX 생성은 부가 기능입니다. 핵심은 수집 근거가 기획으로 이어지고 프리뷰를 확인하는 과정입니다.
